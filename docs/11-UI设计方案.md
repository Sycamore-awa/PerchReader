## 二、约束（这些约束决定了方案的形状，别绕过）

### 2.1 没有 Mac —— 能看到的只有纯 Flutter 部分

| 回路 | 能否看到真实效果 | 说明 |
|---|---|---|
| `flutter test`（Linux VM） | 逻辑与布局 ✅，像素 ⚠️ | 需 golden 才有像素（见 §八.3） |
| Web（Chromium，`just app-web`） | 大部分 UI ✅ | 阅读页有未解的 `manifest.json` 坑（`docs/07` §三） |
| Linux 桌面 | 只有纯 Flutter 界面 ✅ | `flutter_readium` **不支持 Linux 桌面** |
| 真机 / 模拟器 | 一切 ✅ | 无设备（无 Mac） |

**所以**：方案把「阅读页」之外的**所有 UI 都做成纯 Flutter**，并给阅读页做一个 `ReaderHost` 抽象（§八.1），使 chrome、设置面板、进度、目录这些**能在 Linux 上跑起来**。

### 2.2 封面字节现在拿不到

`perch-epub` 能解析出 `cover_href`（`core/perch-epub/src/package.rs:223`），`perch-jobs` 也把它放进精修结果；但 **`perch-ffi` 没有任何「按 href 取资源字节」的方法**。
**所以**：书库的第一公民是**占位封面**（确定性配色 + 书名首字 + 格式角标），真封面是 §九 的待办（`epub.resource`），**不是** M1 的阻塞项。

### 2.3 标注钩子的真实能力（读 `flutter_readium 0.6.2` 源码得出，未在设备上验证）

| 能力 | 结论 | 位置 |
|---|---|---|
| 选区事件 | ✅ `ReadiumReaderWidget.onTextSelected` → `TextSelectionEvent{locator, selectedText}` | `platform_interface/lib/src/reader/reader_selection.dart` |
| 自定义选区菜单项 | ✅ `selectionActions: [SelectionAction{id,title}]` + `onSelectionAction` | 同上 |
| 系统菜单项控制 | ✅ `allowedDefaultActions`（copy/share/lookup/translate/selectAll） | 同上 |
| ⚠️ Android 差异 | 传了自定义 `selectionActions` 会**整体替换** ActionMode → 复制/分享/全选都不再显示（`allowedDefaultActions` 在 Android 无效） | 源码注释 |
| ⚠️ iOS `lookup` | 打开它会**连带**出现「Search Web」（同组不可分离） | 源码注释 |
| 高亮渲染 | ✅ `applyDecorations(groupId, [ReaderDecoration{id, locator, style}])`；`DecorationStyle = highlight / underline / spotlight`，可带 `tint`、`isActive` | `reader_decoration.dart` |
| 点已有高亮 | ✅ `onDecorationInteraction` | `EPUBReaderView+Decorations.swift:29` |
| **选区屏幕坐标** | ❌ **不暴露** | 全包无此 API |

**所以**：① 自绘「浮条贴在选区上方」这条路**走不通**，走系统菜单 + 底部色板；
② 所有高亮 id 直接用**标注的 UUID**，`isActive` 用来表示「搜索命中 / 列表里正在看的那条」。

### 2.4 FFI 现状（三条硬事实，直接影响 UI 性能）

| 事实 | 证据 | 对 UI 的影响 |
|---|---|---|
| 数据面只有 **`bytes_hex`**（十六进制字符串），**没有任何按路径的接口** | `core/perch-ffi/src/lib.rs`（`book.open` / `txt.analyze` / `pdf.analyze` 全是 `hex_to_bytes(required_str(args,"bytes_hex"))`） | 10MB 文件 = 20MB 字符串进出，加上返回体，约 4~6 倍内存放大 → 大文件必须句柄化（§五.2） |
| `PerchCore.invoke` 是**同步** FFI | `dart/perch_core/lib/perch_core.dart:92` | 大文件 decode 会堵 UI isolate → 必须 worker isolate（§五.2） |
| 句柄表上限 **8**（`MAX_OPEN_BOOKS`），且**只有一种句柄类型** | `core/perch-ffi/src/lib.rs:51`、`registry().insert(OpenBook{..})` | TXT 阅读句柄要和后台索引任务抢名额 → 句柄表要加 `kind` 与配额（§五.2 契约） |

另外：`book.open` 会**顺手把全文倒排索引建完**（同文件 `:200`）。阅读路径不该干③阶段的活——M2 打开书只 decode，索引交给 M3 后台。

### 2.5 TXT 在核心侧「没有篇章结构」

`perch-jobs` 明确：TXT 整本书 = **一个章节**，`href` 固定，`toc` 为空（`core/perch-jobs/src/lib.rs:25`、`:602`）。
**所以**：TXT 的目录要么用正则生成**虚拟目录**（§五.7），要么这一版不做目录、只给「页码 + 进度」。

### 3.4 字体与排版

| 项 | 决策 | 理由 |
|---|---|---|
| 字体资产 | **不打包**。iOS 用系统字体（衬线 `Songti SC` / 黑体 `PingFang SC`），Android 用 `Noto Serif CJK` / `Noto Sans CJK` | 体积；与「依赖极薄」的既定口味一致 |

| 数字 | 进度、页码用等宽数字（`fontFeatures: [tabularFigures]`） | 避免翻页时数字宽度跳动 |

```

```

## 五、TXT 自绘（T1）

### 5.1 职责切分：一条判据

> **页断点由 Flutter 的字体度量 + 视口尺寸决定，Rust 那边没有字体度量。**
> 分页放 Rust = 盲猜，而且违反「本地可验」。所以：**Rust 出与字体无关的文本几何，Dart 出分页与绘制。**

| Rust（`perch-txt`，**已实现**） | Dart（本方案要做） |
|---|---|
| 编码探测（BOM → 合法 UTF-8 → `chardetng`）、解码、替换字符计数 | 段落切分、`TextPainter` 测量、装箱成页 |
| 抽样字符↔字节索引（`SAMPLE_STRIDE = 256`）、行索引、`text_range` / `line_text` | 页表、锚点表、缓存键与失效 |
| `locator(char) -> Locator`；`char_offset_of_locator()` 三级回退（txt_offset → byte_offset → progression） | 渲染、翻页、选中、高亮、目录 |
| `context_around`（前后文，M4 重锚定要用） | 设置项与预览 |

### 5.2 三条前置（✅ 已批准）

#### ① FFI 句柄化 + 按路径读（替代 `bytes_hex`）— ✅ 2026-10-18 已落地

> 实现：`core/perch-ffi` 的 `txt.open` / `txt.slice` / `txt.locate` / `txt.offset` /
> `txt.line` / `txt.close`（7 个 Rust 测试 + 18 项 Dart 端到端冒烟）。
> 句柄带 `kind`、配额分开计数、拿错类型报 `HANDLE_WRONG_KIND`，规则见 `docs/02` §三点五。
> 与下面草拟的契约有两处差异：`txt.slice` 的 `chars` 必填且有 2 万上限（一次取整本书
> 是调用方的 bug，明确失败更好）；没有 `txt.headings`（章节识别留到需要时再说）。

现状的问题（§2.4）：10MB 文件要 hex 成 20MB 字符串、Rust 再解回来，`txt.analyze` 还会**把全文当 JSON 字符串吐回**。

拟定契约（与现有 `version` / `book.*` 同风格，错误码沿用 `FFI_BAD_ARGS` / `BOOK_BAD_HANDLE` / `BOOK_TOO_MANY_OPEN` 这套）：

```
txt.open   { "path": "/…/book.txt", "encoding": null }
        -> { "handle": 3, "chars": 4123456, "lines": 121034,
             "encoding": "gbk", "certain": true, "hadErrors": false }

txt.slice  { "handle": 3, "start": 12000, "chars": 800 }
        -> { "text": "……" }                       // 只回当前页要画的那几百字

txt.headings { "handle": 3, "limit": 2000 }        // 可选：正则章节识别下沉（见 §5.7）
        -> { "items": [ { "start": 0, "title": "第一章 灯塔" }, … ] }

txt.locate { "handle": 3, "char": 12000 }          // 复用 perch_txt::locator
        -> { "locator": { … } }

txt.offset { "handle": 3, "locator": { … } }       // 复用 char_offset_of_locator（含回退链）
        -> { "char": 12000 }

txt.close  { "handle": 3 }
        -> { "closed": true }
```

配套改动（都很小，但**必须一起做**，否则句柄表会打架）：

- ~~句柄表加 `kind: Book | Txt`，并给「阅读」类句柄**保留配额**（阅读时最多 1 本，后台索引任务不得挤占）。~~ ✅ 已做：`kind` + 分开计数（`book` 8 / `txt` 4）。
- ~~`MAX_OPEN_BOOKS = 8` 的报错文案要区分「书太多」与「阅读/任务冲突」。~~ ✅ 已做：`BOOK_TOO_MANY_OPEN` / `TXT_TOO_MANY_OPEN` / `HANDLE_WRONG_KIND` 三个码。
- ~~大文件**永远不要**用 `txt.analyze` 那条路（它要全文文本），阅读路径只走 `open` + `slice`。~~ ✅ 已在 Dart 侧把这条写进文档注释（`analyzeText` 标注"只给导入阶段用"）。

#### ② 所有 FFI 调用 isolate 化 — ✅ 2026-10-18 已落地

> 实现：`dart/perch_core/lib/perch_worker.dart` 的 `PerchWorker`
> （`spawn` / `call` / `dispose`，5 项冒烟覆盖）。
> 三个刻意的设计：请求**串行**（worker 里同步处理消息，天然让"打开→切片→关闭"有序）；
> 业务错误跨 isolate **重建**成同一个 `PerchCoreException` 类型与错误码；
> worker 异常退出时**在飞的请求立刻失败**，而不是永远等。
> 另外：`errors` / `exits` 两个端口必须显式关闭，否则 **Dart VM 不会退出**
> （第一版就是"活儿干完了进程不结束"）。
>
> 下面草拟的契约仍然成立：

`PerchCore.invoke` 是同步调用（§2.4）。直接放在 `build`/`initState` 里会把 UI isolate 堵住（10MB decode）。
做法：一个常驻 worker isolate，Dart 侧只保留 `Future<Map<String,dynamic>> call(String method, Map args)`；
解码与任何 >10ms 的工作都排队过去。UI 侧统一 await + 骨架态。

#### ③ 页表持久化

`layoutKey = hash(fontFamily, fontSize, lineHeight, letterSpacing, margins, paraSpacing, indent, viewportW, viewportH, platformFontTag)`。
按 `layoutKey` 存 `PageTable`（页边界 + 稀疏锚点表 char→page），只保留最近 3 个 key。

> ⚠️ **页号绝不入库、绝不跨端同步**：不同平台字体度量不同（iOS 与 Android 的 `Songti SC`/`Noto Serif CJK` 行高就不同）。
> 同步只走 **char offset**（`Locator.perch.txt_offset`）——这正是 `perch-model` 已经设计好的。

### 5.3 数据模型（Dart）

```dart
Block      { int startChar, endChar; BlockKind kind; String text }   // kind: 空行 | 标题 | 正文
BlockSlice { int startChar, endChar; int firstLineIndex, lineCount } // 超长块被切开后的一片
PageItem   { int pageIndex, startChar, endChar; List<BlockSlice> slices }
PageTable  { String layoutKey; List<PageItem> pages; Map<int,int> anchors; bool done; int? totalEstimate }
TxtLayout  { fontFamily, fontSize, lineHeight, letterSpacing, margins, paraSpacing, indent, theme }
```

### 5.4 分页算法（四条规则）

1. **贪心装箱**：逐段 `TextPainter.layout()` 量高度，能塞进剩余高度就连排，塞不下就翻页。
2. **超长块**：整段高度 > 一页时，用 `computeLineMetrics()` **按行边界**切分成若干 `BlockSlice`。
   （很多 TXT 全文无换行，这条不是边角料，是必备项。）
3. **渐进式**：只算「当前页 + 预取 3 页」；前进时增量扩展；向后跳转从**最近的持久化锚点**起算。
4. **总页数未知也不慌**：进度条用 **char 比例**，页码显示「第 12 页 / ≈340 页」——`≈` 来自已算页的字符密度外推。
   这不是妥协：它是「打开 <1s」的前提，也是 Kindle / 微信读书这类产品的通行做法。

### 5.5 渲染与翻页

| 模式 | 实现 | 备注 |
|---|---|---|
| 滚动（默认） | `ListView.builder` over `Block` | **根本不需要分页** —— 先把这条链路做出来，TXT 立刻可用 |
| 平移翻页 | `PageView` over `PageItem`，每页一个 `Text.rich`（段 span） | 需要页表 |
| 仿真卷页（M6，实验） | 对 `RepaintBoundary.toImage()` 的位图做网格形变 | **全程在 Flutter 内，不需要平台截图通道**（对比 EPUB 必须走平台通道，`docs/08` §二） |

TXT 的卷页是三种格式里**唯一能本地验证**的 —— 自绘带来的第二个红利。

### 5.6 选中 → 字符偏移（M4 的地基）

- **v1**：整页包 `SelectionArea`，`onSelectionChanged` 拿到选中字符串 → **在本页的 char 区间内**定位；
  用外层 `Listener` 记住按下坐标，经 `RenderParagraph.getPositionForOffset()` 换成一个锚点 char，用来消歧重复文本。
- **v2（M4 精修）**：自绘选区，直接拿起止偏移，不再依赖字符串匹配。
- **兜底天然存在**：匹配失败就退化成「页 + 前后文 excerpt」——这正是 M4 既定的重锚定策略。

**额外收益（重要）**：TXT 的「标注零漂移」是 **100% 本地可验**的。
给定 `char range + excerpt` 与一组 layout 变体，断言 `char → page → rect` 后仍取回同一 excerpt，
就能在 Linux 上用单测钉死 M4 的验收指标（EPUB 这条只能靠真机）。

### 5.7 目录

`perch-jobs` 明确 TXT 没有篇章结构（§2.5）。分两步走：

1. **v1（Dart，随 M2）**：正则生成虚拟目录 —— `^第[一二三四五六七八九十百千零〇0-9]+[章节回卷篇]`、`^Chapter\s+\d+`、`序章|楔子|前言|后记|尾声`。命中即得 `char offset`，点击跳转即 `goToChar`。
2. **v2（M3，下沉 Rust）**：`txt.headings`（§5.2 契约里已留位），保证跨端目录一致。

### 5.8 性能预算

| 阶段 | 量级 | 目标 | 谁保证 |
|---|---|---|---|
| 10MB 中文 TXT | **≈ 330~500 万字符**（UTF-8 3 字节/字、GBK 2 字节/字）、约 7 千~1 万段 | — | — |
| 读文件 | 10MB | < 50ms | Dart |
| decode（chardetng + encoding_rs） | — | **未测，必须先量**（10MB GBK / UTF-8 各一份） | Rust（worker isolate） |
| 首屏分页 | 1 页 ≈ 420~500 字（17sp / 行距 1.7 / 边距 24 → 约 22 行 × 20 字） | < 30ms | Dart |
| **打开到首屏** | 三项之和 | **< 600ms** | — |
| 每翻一页 | 预取 3 页 | < 30ms（后台） | Dart |
| 全书分页（真跑完） | 约 7 千~1 万页 | 10~40s → **后台增量 + 断点续算，绝不在打开时做** | Dart isolate |

### 5.9 本地能验 / 不能验

✅ 能验（Linux + web）：分页 golden（固定字体 + 固定视口）、页表缓存命中、`char ↔ 页` 映射、
选中→偏移、excerpt 重锚定、目录正则、进度换算、空态/错误态。
❌ 不能验：真实字体度量与手感、iOS 滚动惯性、卷页观感。

### 5.10 风险

| 风险 | 对策 |
|---|---|
| 字体度量跨平台不同 → 页号不可跨端 | 页号**只存在于页表缓存**，同步只走 char offset（§5.2 ③） |
| decode 耗时未知 | **先量**；超标则降级「首屏只解码前 200KB 的整数倍边界」 |
| 超大单段（无换行） | `computeLineMetrics` 行边界切分（§5.4 规则 2） |
| `SelectionArea` 定位精度 | v1 锚点消歧 + excerpt 兜底；v2 自绘 |
| 页表缓存膨胀 | 只保留最近 3 个 `layoutKey` |
| 分页在后台把 CPU 吃满 | 复用 `perch-pipeline` 的「并发上限 + 让位前台」思路（Dart 侧同理：分片 yield） |

## 六、PDF：只读

### 6.1 决策

**PDF 只支持阅读，不支持标注 / 笔记**；渲染走 `flutter_readium` 自带的 PDF navigator，**不引入 `pdfrx`**。

### 6.2 能力现状（读 `flutter_readium 0.6.2` 源码与 CHANGELOG 得出，**未在设备上验证**）

好消息：插件**自带** PDF 渲染，零新增依赖。

| 平台 | 实现 | 位置 |
|---|---|---|
| iOS | `PDFNavigatorViewController`（Readium **swift-toolkit** → **PDFKit**） | `ios/flutter_readium/Sources/flutter_readium/reader/PDFReaderView.swift` |
| Android | `PdfiumNavigatorFragment`（Readium **kotlin-toolkit** → **PDFium**） | `android/src/main/kotlin/dk/nota/flutterreadium/navigators/PdfNavigator.kt` |

能用的能力：`setPDFPreferences`（`PDFLayout` = `paginated` / `scrollVertical` / `scrollHorizontal`、`PDFFit`、`pageSpacing`、`readingProgression`；iOS 另有 `offsetFirstPage` / `spread`）、
`goToProgression`（用 `metadata.numberOfPages` 换算成页）、`toPhysicalPageIndex`、
以及 **TOC 富化**（把 `#page=N` 的目录项贴到 locator 上）。

**做不到的（这就是「只读」的由来）**：

| 能力 | 结论 | 证据 |
|---|---|---|
| 高亮 / 笔记 | ❌ iOS `applyDecorations` 明确 **no-op**（注释：`PDFNavigatorViewController` 不 conform `DecorableNavigator`，swift-toolkit 3.9.0）；Android 头注释写「Decorations are not exposed by the upstream PDF navigator」 | `PDFReaderView.swift`、`PdfNavigator.kt:40` |
| 自定义选区菜单 | ❌ `configureSelectionActions` → 「PDF has no custom selection-action UI」 | `PDFReaderView.swift` |
| 全文搜索 | ❌ Android 直接抛错「PDF search is not supported on Android: kotlin-toolkit does not ship a SearchService for PDF publications」 | `ReadiumReader.kt:1518` |
| Web | ❌ 完全不支持（CHANGELOG: "PDF is not supported on Web"） | `CHANGELOG.md:601` |
| Android PDF 偏好 | 🔶 尚未落地（上游 roadmap Phase 5） | `PdfNavigator.kt:40` |

### 6.3 已知缺口与影响（诚实标注）

1. **PDF 不能搜** → M3 的全文搜索只覆盖 **EPUB / TXT**。搜索 UI 要能表达「本书不支持搜索」，而不是给个永远转圈的框。
2. **PDF 在本机完全看不到**（无 Mac、web 不支持）→ PDF 相关改动只能靠云 CI 编译 + 盲改。
   因此 **PDF 的实现顺序放到最后**（M2 末尾），且**不许**让 PDF 的特例污染 EPUB/TXT 的代码路径。
3. PDF 的进度与定位用 Rust `perch-pdf` 的结构信息（页数/大纲/元数据）+ Readium 的 locator（`Locator::new_pdf(page, totalPages)`，`href` 固定 `pdf:`，`perch.pdf_page` 存页号 —— `core/perch-model/src/locator.rs:272`）。

### 6.4 回退路径（今天不做，但要留门）

**`ReaderHost` 抽象必须保留**（§八.1）：将来若 PDF 需要标注，或 PDF 需要在本机可见，就换 `pdfrx` 实现（自绘 → 可加自己的高亮层，`Locator.perch.pdf_rect: [f32;4]` **模型侧已经就绪**，`core/perch-model/src/locator.rs:155`）。
届时先跑一天 spike：web 能否跑 / 打开耗时 / 滚动帧率 / 文本选择 / 文本搜索 / 体积增量。
**注意**：我没有联网核实 pdfrx 的平台矩阵与体积，上面这些是 spike 要回答的问题，不是结论。

## 七、各 UI 面

### 7.1 书架

- 布局：**网格（默认，3 列）/ 列表**切换；网格 `GridView.builder` + `cacheExtent`，每张卡 `RepaintBoundary`，封面按目标尺寸解码。
- 排序：最近阅读 / 标题 / 作者 / 导入时间；筛选：格式（EPUB/PDF/TXT）、状态（未开始/在读/读完）、导入状态。
- 搜索框：标题/作者前缀匹配（本地），**不与全文搜索混用**（全文搜索在书内，见 §7.7）。
- 长按书卡：详情 / 标记读完 / 移出书架 / 重新精修 / 删除（删除要二次确认 +「同时删除文件」开关）。
- 1000 项纪律：**不做**逐项阴影、**不做**逐项位移动画、封面淡入只对**当前屏内**项做。

### 7.2 导入与后台任务

| 状态点 | 含义 | 用户可做 |
|---|---|---|
| 灰 | 已登记（①阶段完成，还没精修） | — |
| 黄 | 精修中 / 索引中（②③） | 暂停、优先处理 |
| 绿 | 已索引（可全文搜索） | — |
| 红 | 失败（附错误码） | 重试（`perch-pipeline` 已有手动重试） |

- 书架顶部胶囊：「正在精修 7 本 · 已索引 213 本」，点击 → **任务面板**（列表 + 单条重试 + 全部暂停/继续）。
- 「感知上架」的产品含义写死为：**用户看到 1000 本可交互的卡（封面可用占位）**（对应 `docs/04` #15 的建议口径）。

### 7.3 阅读页 chrome

- **手势**：左右 70px 边缘点击翻页（`ReadiumReaderWidget` 自带该热区）；点击中央呼出/收起 chrome；
  滚动模式下无翻页热区（用 `disablePageTurnsWhileScrolling` 同款语义控制）。
- **顶部**（呼出时出现）：返回、书名（超长省略）、同步状态点。
- **底部**：进度滑块 + **章节刻度**（EPUB 用 TOC href 折算；TXT 用虚拟目录；PDF 用页数）+
  目录 / 搜索 / 笔记 / 排版 四个入口 + 等宽数字的「第 12 页 / ≈340 页」。
- 状态：首屏加载用**纸色骨架**（不用转圈），失败给「重试 / 用其他应用打开」。
- 阅读中**不显示**任何进度提示（除用户主动呼出），保持纸感。

### 7.4 排版设置面板（底部抽屉，带实时预览）

EPUB 走 `EPUBPreferences`（能力面很宽，**这是本项目最容易做出差异化的地方**）：

| UI 控件 | `EPUBPreferences` 字段 |
|---|---|
| 字号 | `fontSize` / `typeScale` |
| 行距 | `lineHeight` |
| 字距 | `letterSpacing` |
| 段距 / 段首缩进 | `paragraphSpacing` / `paragraphIndent` |
| 页边距 | `pageMargins` |
| 字体（衬线/黑体） | `fontFamily`（配 `fontFamilyDeclarations`） |
| 对齐 | `textAlign` |
| 主题背景 / 字色 | `backgroundColor` / `textColor`（+ `imageFilter` 可选） |
| 翻页方式 | `scroll`（滚动/翻页）、`columnCount`、`spread`（iPad） |
| 竖排 | `verticalText`（中文场景的加分项） |
| 是否遵循出版方样式 | `publisherStyles`（注意：很多设置要它关掉才生效） |

TXT 用同一套面板，映射到 `TxtLayout`；PDF 只给「布局（分页/纵向滚动/横向滚动）+ 适合宽度」。
面板底部三个动作：**恢复默认 / 应用 / 应用并记住**（记住 = 写入我的偏好默认值）。

### 7.5 目录抽屉

- EPUB：`publication.toc`（层级缩进 + 当前章节高亮 + `skipToNextTOC` 快捷）。
- TXT：虚拟目录（§5.7）。
- PDF：`perch-pdf` 的大纲（两级嵌套已还原，`docs/10`）。
- 每项右侧显示进度百分比（EPUB 用 locator 折算；PDF 显示页码）。

### 7.6 标注（EPUB / TXT；**PDF 不做**）

```
长按选中文本 → 系统菜单出现「高亮」「笔记」（+ 复制）
  「高亮」→ 底部色板（4 色，点选即生效，不弹二次确认）
  「笔记」→ 底部半屏编辑器（显示摘录 + 输入框 + 保存）
点已有高亮（onDecorationInteraction）→ 底部操作条：改色 / 编辑笔记 / 复制 / 删除
```

- 高亮渲染：`applyDecorations(groupId, [ReaderDecoration(id: annotationId, locator, style: highlight+ tint)])`；
  **id 必须用标注 UUID**（M5 同步按 UUID 逐条独立，减少冲突面）。
- 「正在看的那条」用 `isActive: true`（搜索命中跳转、笔记列表进入时）。
- 书签：**不加选区**，直接落当前 locator（顶部按钮或菜单）。
- 笔记 Tab 的卡片：书名 + 摘录（最多 3 行）+ 笔记 + 时间 + 颜色条；左滑删除、右滑导出。
- 导出：Markdown（`# 书名` → `## 章节` → `> 摘录` + 笔记），M4 交付。
- ⚠️ 平台差异：Android 上传自定义 `selectionActions` 会**替换**系统 ActionMode（复制/分享消失）——iOS 优先不受影响，Android 要单独设计（后续里程碑）。

### 7.7 搜索（M3）

- 书内搜索：**分两条路**——EPUB 用 Readium `searchInPublication`（返回带 locator 的结果）；TXT 用 Rust 索引（`book.open` / `book.search`，命中的 `locator` 是**粗定位**，需在页内按文本重锚定，见 `docs/02` §五）。
- UI：输入即搜（防抖 200ms）、结果按章节分组、命中项高亮（`isActive`）、点击跳转、上下一条。
- **PDF 明确提示不支持**（§6.3）。
- 书架级「全文搜索全部书」放到 M3 之后再评估（现在没有跨书索引）。

### 7.8 同步面（M5）

- 书架/阅读页的**状态点**：已同步 / 同步中 / 离线 / 有冲突（`seal` 色）。
- 我的 →「同步」：上次同步时间、待上传条数、**冲突记录面板**（每行：书、字段、保留值、丢弃值、时间）。
- 书卡的**双进度**（当前位置 / 最远位置，§4.3）就是 `docs/04` #9 的 UI 呈现；
  无论最终选「最后 / 最远 / 混合」，**两条都画**，不需要用户理解策略。
- 涉及 `perch-sync` 的 `merge` / `delta`（已有）与 `ProgressRule`（`LastWriteWins` / `FurthestWins` 已实现，混合未实现）。

### 7.9 空态 / 错误态 / 首启动

| 场景 | 设计 |
|---|---|
| 空书架 | 一句话价值主张 + 「导入书籍」主按钮 + 「支持 EPUB / PDF / TXT」；不放插画（省体积） |
| 首次打开书 | 纸色骨架 + 只在 >800ms 时出现「正在打开…」 |
| 打开失败 | 错误码 + 人话解释 + 「重试」「用其他应用打开」「反馈」 |
| 存储失败 | 顶部条（不是弹窗）：进度无法保存，阅读继续 |
| 无搜索结果 / 无笔记 | 居中一句 + 对应动作按钮 |

### 7.10 无障碍与本地化（M6）

- `ReadiumReaderWidget` 已有 `goBackwardSemanticLabel` / `goForwardSemanticLabel` / `toggleShowControlsSemanticLabel`，接中文文案即可。
- UI 文字跟随 Dynamic Type；正文用独立字号（§3.4）。
- 对比度：`inkSoft` on `paper` ≥ 4.5:1（实现时用工具核一遍）。
- 本地化：中文优先，文案集中到一个 `strings` 表，预留英文（先不接 `intl`，避免依赖）。

### 8.1 `ReaderHost` 抽象（**M2 的第一件事**）

```

├── EpubHost  → ReadiumReaderWidget（真机才有效）
```

- ⚠️ 排版相关 golden 必须固定视口尺寸与字体，否则基线会因环境漂移。

## 十、实施顺序（ticket 草稿）

### M1（书架）

1. `design/`：token + 基础组件（Text/Button/Card/EmptyState/状态点/进度条）→ 带 golden。

3. 书架网格（占位封面 + 确定性配色）+ 列表模式 + 排序/筛选（先内存实现，C 未定前不引入 SQLite）。
4. 书卡双进度（读 `ProgressStore`）+ 状态点（读内存中的导入状态）。
5. 任务胶囊 + 任务面板（先接假数据；真数据等后台驱动循环接上）。
6. 空态 + 错误态。

### M2（阅读）

7. **`ReaderHost` 抽象 + `FakeHost`**（第一件事，后面全部依赖它）。
8. 阅读 chrome（顶部/底部/手势/进度条/章节刻度）+ 打开失败态。
9. 目录抽屉（EPUB 真数据；TXT 虚拟目录）。
10. 排版面板（`EPUBPreferences` 映射 + 实时预览 + 默认值持久化）。
11. **TXT：`txt.*` 句柄化 FFI + worker isolate**（§5.2 ①②）。
12. TXT 滚动模式（`ListView` over Blocks）→ 立即可用。
13. TXT 分页（§5.4）+ 页表缓存（§5.2 ③）+ 平移翻页。
14. PDF 只读接入（放最后，且只走 `PdfHost`）。

### M3（搜索）/ M4（标注）/ M5（同步）

18. 同步状态点 + 冲突面板 + 双进度接真数据。
