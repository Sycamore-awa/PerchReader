## 🔴 阻塞级（不定无法推进 M0/M1）

### 4. GitHub 仓库设为公开还是私有？
这个决定**直接决定"没有 Mac 时能不能干活"**：

| | 公开仓库 | 私有仓库 |
|---|---|---|
| macOS runner | **免费、额度不限** ✅ | ~**200 分钟/月**（2000 分钟 ÷ 10 倍倍率） |
| 每月够几次构建 | 想跑多少次跑多少次 | ≈ **13 次 × 15 分钟** |
| 按需付费 | — | $0.062/分钟 |

对一个"用 CI 当编译器和测试机"的项目，200 分钟/月基本不够用（M2 集成期一天就可能跑 5~10 次）。
**我的建议**：公开仓库；或者公开一个只用于 CI 的镜像仓库（但代码就公开了，需你判断是否可接受）。
如果代码必须保密，就要算一下每月 CI 预算（按 40 次 × 15 分钟 ≈ 600 分钟 ≈ $37/月估算）。

### 5. iOS 18 还是 26？（第 2 项决策的细化）
你选的是我给的合并选项，需要确认到底是哪个：
- **iOS 18 起（推荐）**：覆盖率高，现代 API 基本都有，成本低
- iOS 26 起：只能用最新 API，但用户面极窄

### 6. 要不要做一个"本地开发壳"（Tauri/Web + Rust WASM）？
- **做**：本地立刻能看到 EPUB/TXT 渲染、翻页、标注、搜索效果；反馈回路从 15 分钟降到 1 秒；额外投入约 1~2 周
- **不做**：按原计划只做 iOS，所有界面效果只能在云 CI 截图里看
- 我倾向**做**（这是解决"看不到效果"最有效的手段），但它超出了"只做 iOS"的范围，需要你拍板

### 7. 是否愿意在关键阶段租用云端 Mac？
MacinCloud / MacStadium 按小时或按月租，能恢复**交互式 Xcode**。
最需要的阶段是 **M2（Readium 集成与渲染调试）** 和 **M6（性能/手感打磨）**。如果不租，这两段的效率会显著偏低。

## 🟡 高优先级（M1~M5 之前定）

### 8. 同步后端用哪套？
- 自建 Rust API（`axum`）：可复用核心的 Locator 校验；要自己运维
- Supabase：开箱即用；但校验逻辑要重写
- CloudKit：按项目目标仅作辅助
- **建议**：自建最小 API + **Sign in with Apple**（不自建密码体系）

### 9. 阅读进度的合并语义？
- A. 最后阅读位置（按时间）
- B. 最远阅读位置
- C. **混合（推荐）**：默认最远，但用户显式跳转时采纳该位置
- 这个定义**直接决定"冲突率 <1%"的口径**，必须早定

### 10. TXT 要支持到多大？
- ≤20MB：全量解码 + 分页缓存
- \>20MB：分片映射 + 块索引表
- 需要知道你实际的场景（会不会有人导入 50MB 的 txt 合集？）

## 🟢 中优先级（M3 前后定）

### 11. 中文分词
**建议 CJK bigram + Unicode 词边界**（免词典、召回高、索引小）；备选 `jieba-rs`（更准，但词典 ~10MB）

### 12. 全文搜索实现
**建议自研倒排 + `fst`**（可控、能精确映射 Locator）；`tantivy` 功能强但对移动端偏重

### 13. 是否需要在线补全封面/元数据
（豆瓣 / Google Books）涉及网络依赖与隐私声明，建议 M3 之后再说

## ⚪ 确认类（一句话即可）

### 14. 目标市场
我按**中文用户优先**设计（GBK/Big5 编码、CJK 分词、中文排版）。确认？是否要繁体/日韩？

### 15. "1000 本感知上架 <10s"的定义
我按 **"用户看到 1000 本可交互的列表"** 理解（封面可用占位）。确认？
若要求"1000 张封面全部渲染"，10 秒不现实。

### 16. 仓库形态与初始化
- 确认单仓 monorepo（`core/` + `ios/` + `docs/`）？
- 要不要我 `git init` 并建首个提交？配 `.gitignore`（排除 `target/`、`*.xcodeproj`、`DerivedData/`）？
- 有远端仓库地址的话给我

### 17. 仿真翻页（page-curl）优先级
我放在 M6。**在没有 Mac、无法用 Instruments 调优的前提下，这个功能很难做好** —— 它极度依赖手感调参。建议明确推迟到"能拿到 Mac"之后。

### 18. 崩溃上报
**建议 MetricKit 起步**（系统自带、隐私友好、免费；但只有聚合数据、延迟约 24h），需要精确定位时再加 Sentry

### 19. 后台精修/索引的调度激进程度
- 保守：仅充电 + Wi-Fi + 空闲时跑（省电，但 1000 本要几天才索引完）
- 激进：允许蜂窝网络，前台空闲就跑（快，但耗电/耗流量）
- 建议保守偏中间：默认 Wi-Fi + 非低电量；用户可在设置里改成"尽快"

## 附：我替你做的假设（不符请指出）

4. 先做"能读、能标、能同步"，DRM/支付只留接口
